PROJECT LUMIERE (ESP32 / TinyGPS++ / FreeRTOS / HTTP AP) Autonomous Streetlamp Outage Detection, 5-Meter Geolocation Fix & Municipal Telemetry Dispatch

An autonomous, low-cost Internet of Things (IoT) hardware device engineered to mount directly beneath municipal streetlights. As public luminaires experience bulb defects and electrical faults, dangerous nighttime blind spots emerge that cause severe vehicular accidents and jeopardize pedestrian safety. Conventional municipal maintenance relies on citizens manually remembering and reporting issues during daytime hours—a friction-heavy process with days of delayed intervention. Lumiere eliminates this lag: combining high-sensitivity Light Dependent Resistor (LDR) photometric sensing, hardware serial GY-NEO6MV2 GPS satellite tracking, and an ESP32 Wi-Fi SoftAP HTTP dispatch server to transmit immediate failure alarms, precision coordinate pins, and escalating alerts to local authorities.

Engineering Architecture

Four Core Pillars of the Lumiere IoT Ecosystem

A fail-safe embedded design integrating robust analog photometry, hardware serial satellite kinematics, local micro-server networking, and dynamic auditory alarms.

1. Optical LDR Sensing & Schmitt Thresholding

A CdS photoresistor mounted on the luminaire underside continuously samples the lamp's downward light cone. During healthy night operation, the lamp casts sufficient incident photons to maintain analog readings above 3000 ADC (~60+ Lux). When the luminaire burns out or loses line power, the ambient reading plummets to near-black (<1200 ADC), immediately satisfying the failure condition.

  • Voltage Divider: CdS cell paired with 10kΩ metal-film resistor to ground
  • GPIO 34 ADC: High-impedance analog input with 12-bit SAR digitization
  • Transient Filtering: Moving average window filters out passing car high-beams

2. GY-NEO6MV2 Satellite Geolocation Engine

Streetlamps are distributed by the tens of thousands across urban sectors. Rather than requiring technicians to manually configure GPS coordinates or cross-reference pole ID databases, Lumiere features an autonomous onboard GY-NEO6MV2 GPS module with an active ceramic patch antenna.

  • Hardware UART1: Dedicated serial channel (RX 16, TX 17) at 9600 baud
  • TinyGPS++ Parsing: Encodes NMEA $GPRMC and $GPGGA strings
  • Sub-5m Accuracy: 50-channel tracking engine with <1 second hot starts
  • Instant Map URL: Generates direct maps.google.com/?q=lat,lng deep links

3. ESP32 Wi-Fi SoftAP & Municipal HTTP Server

In many municipal corridors, public Wi-Fi or cellular GSM subscriptions for every pole are cost-prohibitive. Lumiere acts as an autonomous Wi-Fi Access Point (SoftAP) broadcasting an SSID (Lumiere) with an embedded HTTP micro-server running on port 80 at 192.168.4.1.

  • Zero Subscription Cost: No recurring monthly SIM card fees required
  • Drive-by Telemetry: Municipal patrol vehicles fetch batch telemetry passively
  • Standard HTTP Payload: Formatted plain-text or JSON telemetry streams
  • Extensible: Easily pairs with ESP-NOW mesh or LoRa for long-range gateways

4. Escalating Piezo Alarm & Admin Override

When severe nighttime lamp failures occur, an acoustic 85 dB piezo buzzer triggers with an escalating beeping pattern to alert neighborhood patrol personnel and passersby. For field service technicians, an external tactile button (GPIO 21) provides an immediate hardware interrupt override.

  • Severity-Scaled Beeps: Beeping interval accelerates with deeper darkness
  • GPIO 21 Interrupt: Hardware interrupt with debounce logic
  • Admin Toggle: Inverts alarm flag (light = !light) to silence during repairs
  • Fail-Safe Reset: Automatically re-arms when daybreak or replacement occurs

Firmware Excerpt: `main.ino` (ESP32 C++ Arduino Core) C++ / FreeRTOS 
#include <WiFi.h>
#include <TinyGPSPlus.h>
#include <HardwareSerial.h>

#define buzzer 23
#define ldr 34                 // Analog input (GPIO 34: ADC1_CH6)
#define interrupt_Button 21   // Tactile admin silence button

const char *ssid = "Lumiere";
const char *password = "12345678";
WiFiServer server(80);
TinyGPSPlus gps;
HardwareSerial gpsSerial(1);  // Hardware UART1 (RX=16, TX=17)

void setup() {
    Serial.begin(9600);
    pinMode(ldr, INPUT);
    pinMode(interrupt_Button, INPUT_PULLUP);
    pinMode(buzzer, OUTPUT);
    digitalWrite(buzzer, LOW);

    gpsSerial.begin(9600, SERIAL_8N1, 16, 17); // GPS baud
    WiFi.softAP(ssid, password);
    server.begin();
}

void loop() {
    get_coordinates();
    int ldrValue = analogRead(ldr);
    String resultString = String(ldrValue) + " | " + coord;

    // Failure condition: Darkness < 3000 ADC and not manually silenced
    if (ldrValue < 3000 && light == false) {
        digitalWrite(buzzer, HIGH);
        delay(300);
        digitalWrite(buzzer, LOW);
        delay(300);
    } else {
        digitalWrite(buzzer, LOW);
    }

    // Handle Admin Override Button
    if (digitalRead(interrupt_Button) == LOW) {
        light = !light;
        while (digitalRead(interrupt_Button) == LOW) { delay(10); }
    }

    // Serve incoming HTTP telemetry requests
    WiFiClient client = server.available();
    if (client) {
        client.println("HTTP/1.1 200 OK");
        client.println("Content-Type: text/plain");
        client.println("Connection: close\n");
        client.println(resultString);
        client.stop();
    }
    delay(30);
}
